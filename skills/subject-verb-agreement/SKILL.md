# 主谓一致 · Subject–Verb Agreement

把孩子在主谓一致上的具体困惑变成可以观察、操作、解释的学习过程。当前重点是一般现在时的基础形式，不覆盖所有复杂主语和特殊一致关系。成功标准是孩子能够说明选择的理由，并在换了主语、单词或语境后再次判断；点击正确答案和通关本身不等于掌握。

## 确定这一课教什么

- 优先采用用户已经提供的年级、语言、教材和困惑。缺少信息时，按小学三年级、中文讲解、基础英语词汇设计，并简短说明假设。只有缺失信息会改变教学目标时才询问。
- 每次围绕主谓一致中的一个难点或一组紧密相关的区别。先找出孩子混淆的判断步骤，例如“是否需要变化”和“变化如何拼写”，不要一开始把全部规则堆给孩子。
- 没有教材原文时，使用自编例句，不声称与某出版社、某年级单元或地区课程完全同步。
- 用户只要讲解、题目、方案或文档时，交付对应内容，不自动扩大为完整应用或发布工作。

## 教学设计

### 先看例子，再解释术语

用孩子认识的人物、动物和日常动作。第一次出现术语时，把术语和问题放在一起，例如“主语：谁在做？”“动词：做什么或处于什么状态？”。

优先使用只改变一个条件的对比例句，让孩子知道是什么引起了变化。例如先比较 `She plays.` 和 `They play.`，再比较 `She plays.` 和 `Does she play?`。不要同时更换人物、时态、词汇和句型，让变化原因变得难以辨认。

规则必须说明适用范围。故事、角色和口诀用来帮助记忆，后面要能对应到真实语法，不能让孩子只记住“她后面永远加 s”一类错误结论。

### 让操作揭示规则

根据知识点选择有教学作用的交互：切换主语、改变句型、拼接句子、观察词尾变化，或在时间线上选择语境。每次操作让相关单词和解释一起更新。

动画表现具体变化，例如词尾移入、y 被替换、小助手出现后主要动词恢复原形。点击切换配上装饰动画只能称为轻量互动，不声称已经制作配音动画或完整冒险游戏。

默认采用“短讲解 → 自由试一试 → 小量练习 → 回看错因”的路径；用户指定其他形式时按指定形式设计。课数、题数、角色和奖励不固定，不必每个子专题都复制同一套页面。

### 用练习区分错因

- 从识别条件，到选择正确形式，再到换语境应用，逐步增加难度。每题只承担清楚的学习目的。
- 干扰项对应真实误解，例如把 `play` 写成 `plaies`，而不是随意制造不存在的词来凑选项。
- 错误反馈说明“这次该看哪个条件”，并允许再试。提示先指出判断线索，需要时再给完整解释和正确例句。
- 错题记录应包含题目或稳定题目 ID、知识点、选择和错因类型；能够按错因提供同类但不完全相同的复习题。
- 区分独立答对、提示后答对和尝试后答对。不要因为重试后过关就报告“全部掌握”。默认不强制限时，也不因答错扣除学习机会。

## 核心内容：一般现在时与第三人称单数

以下规则用于一般现在时的基础教学；过去时和进行时用于帮助辨别适用范围，不扩展为完整时态课程。

### 判断顺序

1. **找主语。** 谁在做？不能根据宾语有几个决定动词形式。`She eats apples.` 中 `eats` 随主语变化，`apples` 的 s 表示名词复数。
2. **分清人称和数。** I / we 是第一人称；you 是第二人称；he / she / it 是第三人称单数。Tom、my mum、the cat 在这些例子中可分别换成 he、she、it。`Tom and Lily` 指两个人。I 和指一个人的 you 都不能因为“只有一个人”就被归为第三人称单数。本课用 they 表示复数，不将其描述为英语中唯一的用法。
3. **看时态和句型。** 一般现在时可表达习惯、事实和状态，不等于“此刻正在做”。在本课普通动词的肯定句中，第三人称单数主语搭配相应动词形式。`She is playing now.` 和 `She played yesterday.` 只作时态对比，不能套用直接加 s 的规则。
4. **检查小助手。** 普通动词的一般现在时否定句、一般疑问句用 do / does；does / doesn't 后主要动词用原形。can 等情态动词后也用原形。限制在本课句型内，不宣称一切疑问句都这样构成。
5. **确定需要变化后，才判断拼写。** 按下面的常见变化练习。

| 类型 | 示例 | 要避免的误解 |
| --- | --- | --- |
| 通常直接加 s | like → likes；eat → eats | like 本来有 e，不必再加一个 e |
| 常见 ch、sh、s、x、z 结尾加 es | watch → watches；wash → washes；miss → misses；fix → fixes；buzz → buzzes | 先用这些常见词，不把简化口诀推广到所有特殊拼写或发音 |
| 辅音字母 + y：去 y 加 ies | study → studies；fly → flies | 不是所有 y 结尾都变 ies |
| 元音字母 + y：保留 y 加 s | play → plays；enjoy → enjoys | 判断的是 y 前面的字母；基础元音字母为 a、e、i、o、u |
| 常用变化单独记 | go → goes；do → does；have → has | 不写 haves，不说所有 o 结尾都加 es |
| be 动词另学 | I am；he / she / it is；you / we / they are | 不生成 bes、ams；She is happy. 提问用 Is she happy? |

典型对比：`She plays.` / `She doesn't play.` / `Does she play?` / `She can play.`。讲清 does 可以作提问、否定的小助手，也可以是主要动词 do 的变化，如 `He does his homework.`。

覆盖关键边界后再扩大题量：I、单个人的 you、单个人名、两个人、my mum、一个动物与多个动物、study/play、have、does、can，以及名词复数和动词变化的区别。

## 制作和交付

- 若用户要在聊天中探索且环境支持互动展示，使用该环境实际可用的展示能力；缺少该能力时可交付可运行的独立网页，说明如何打开。不要依赖某个用户机器上的路径或未提供的专有工具。
- 若用户要下载、放到 GitHub 或交给其他家长使用，生成包含所需样式和脚本的独立网页，或遵循已有项目的结构。不要直接把依赖聊天宿主样式、状态接口的片段当作可独立运行的成品。
- 固定题库与规则反馈优先在浏览器内完成，无需为了简单教学加入账号、服务器或 AI 接口。确有动态对话等需求时再采用相应能力。
- 使用能点按也能用键盘操作的控件。手机窄屏内容应重排；关键提示不依赖悬停或单一颜色；动画尊重减少动态效果设置。
- 需要保留学习进度时，说明保存位置和范围。浏览器本地记录不自动跨设备同步；存储失败时仍应允许当次练习，不承诺记录已成功保存。
- 与已有学习地图结合时，先核对实际节点，再添加资源关联。保留原节点 ID 和来源，把新课程标为自编活动；不根据地图参考年龄推断孩子应已掌握，也不将活动通关自动写成地图能力达标。

## 检查与说明

交付前核对英语例句、中文释义、规则范围、答案唯一性和干扰项解释。对开放拼句等任务接受合理的多种答案，避免把唯一字符串当作唯一合法表达。

制作了游戏时，检查主要交互确实改变句子和反馈，进度不会被重复点击刷高，答错后可重试，错题复习有效；有存储时检查恢复与失败情况。在可用环境中检查窄屏和键盘操作。无法进行的浏览器检查应如实说明，不能把静态检查说成已运行验证。

最终交付包含可用结果、简短玩法和必要的运行限制。只完成设计或文档时，明确这是供后续生成使用的 Skill，不宣称已生成、安装或上线完整游戏。
